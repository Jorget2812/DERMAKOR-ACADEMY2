# Technical Documentation Skill

**Goal:** Ensure all code and system knowledge is clearly documented and easily discoverable.

## Steps

1.  **Code Documentation:**
    *   Write TSDoc for all public functions, components, and interfaces.
    *   Provide clear explanations for complex logic or business rules.
2.  **System Diagrams:**
    *   Create Mermaid diagrams for complex data flows or architectures.
    *   Maintain an up-to-date high-level architecture overview.
3.  **Knowledge Base Management:**
    *   Update `.claude/memory/` files after significant decisions.
    *   Ensure READMEs are clear and actionable for new developers.
4.  **Documentation Audit:**
    *   Check for stale documentation and update or remove it.
    *   Verify link integrity across internal documentation.

## Rules

*   **Actionable Docs:** Documentation must lead to action, not just description.
*   **Self-Documenting Code:** Prioritize clear code over extensive comments.
*   **Visual first:** Use diagrams for complexity; text for detail.
*   **Keep it Current:** Documentation is part of the "Definition of Done".

## Expected Output

*   Clear, accurate, and visually supported documentation of features and decisions.
